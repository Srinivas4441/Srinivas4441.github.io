Operations Executive – Inventory Planning & Control

Planning
  • Run replenishment planning through two daily crons: a morning cron (20 lakh capacity cap) and an evening cron (14 lakh capacity cap). The system utilizes the caps during each run.
  • Calculate the deficit at FSN × Dark Store level as Target Units − (DS in-transit + DS ATP), using the DS_Target_Master, DS_Network_Master and SMIT_QAAS CSV files stored in Google Cloud Storage (GCP), and map each DS to its P0/P1 source hubs.
  • Allocate source hub (SH) inventory to the deficit through an R-based STN allocation script: apply case-pack rounding, block hardstop and non-live dark stores, FSN × DS exclusions and the Mini store FSN list, then allocate whitelisted-seller lots with the nearest non-promisable date first, excluding expired lots.
  • Generate the STN upload templates and a reconciliation file that explains every unallocated unit (hold, DS not live, excluded, no ATP, expired).
  • Use R scripts and Azkaban scheduled jobs to automate recurring planning and data-update tasks.

Step 1

Target

Set the target units for each FSN × Dark Store from DS_Target_Master.

Step 2

Deficit

Target minus DS in-transit (SMIT_QAAS) and DS ATP gives the deficit. Each DS maps to its P0 and P1 source hubs.

Step 3

Filter

Round to case packs. Block hardstop and non-live dark stores, FSN × DS exclusions, and Mini stores for FSNs not on their list.

Step 4

Allocate

Take SH store inventory from whitelisted sellers, drop expired lots, and allocate the nearest non-promisable date first.

Step 5

Create STNs

Generate the STN upload templates for source hub to dark store.

Step 6

Reconcile

A reconciliation file shows every unallocated unit: hold, DS not live, excluded, no ATP or expired.

The input files are CSVs stored in Google Cloud Storage (GCP): DS_Target_Master, DS_Network_Master and SMIT_QAAS. The scripts are written in R and scheduled on Azkaban.
